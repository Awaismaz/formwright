## Verdict

The engines are strong. Every hand check passed: beam, pin shear, M10 bolted joint and shaft fatigue. Mates solve in about
0.1 s, interference volumes are exact, the drawing read was 13/13 correct, and the drawing-to-model round trip was exact.
The shell and auth flows look professional. But a paying designer would lose trust on day one in six ways, and each is a
theme rather than a single bug.

## Six cross-cutting themes

1. **The money story is wrong.** The Studio promises "≈ 40 tokens". Real runs cost 246–338. One template part spends 260 of
   the 300 trial tokens, one drawing-to-model run drives the balance negative, and the balance can go to −233.
   (PLT-01, PLT-16, STU-07, AMI-03)
   *Fix:* an honest, measured estimate; a hard per-run budget with a live meter; a trial sized for about 3 real parts.

2. **Some outputs are geometrically wrong, and the checks don't catch it.**
   - A one-edge fillet rounds the whole corner (STU-01).
   - Drawing dimension values swap spans while CHK-12 still passes (MAKE-01).
   - Fastener auto-fit puts the nut inside the plate on the demo parts (AMI-01).
   - Through holes are read as blind (AMI-02).
   - Ø14 clearance holes are called "M16 tap drill" (MAKE-12).

   *Fix:* each fix needs a regression test with the measured numbers, and the check that missed it gets strengthened.

3. **Edits are fragile.** One manual fillet blocks every later parameter change (STU-03). Refreshing an assembly after a
   dimension change breaks mates, and that is reported with a green toast (AMI-05/06/07). A slow worker start throws every
   later build reply off by one (STU-04).
   *Fix:* references that survive dimension changes; "repair, don't block" when they can't; build replies matched to the
   job that asked for them.

4. **Honesty leaks.**
   - The landing page shows "Write model.py" and promises "manufacturable" CAD (PLT-02/03).
   - Raw Python errors and a Source tab are visible (STU-05/06).
   - "Verified calculation" means two different things (MAKE-03).
   - Sign-offs stay "Verified" after the part changes (MAKE-02).
   - A paywall page advertises mates that don't exist (AMI-04).
   - The agent's own instructions appear as the user's message (AMI-16).
   - Tour and pricing copy still says most modules are Preview (PLT-04).

5. **The modules feel like separate apps.** Each module has its own header and its own staleness rule. The Studio never
   says which deliverables went stale, and advice is read-only: no finding links back to a fix.
   (MAKE-08/15/16, AMI-22, PLT-09)
   *Fix:* one release concept ("Issue Rev A") that every module compares against, and a fix-it loop from findings.

6. **The first run is long, and the differentiators are invisible.** The path is a verification wall, 5 onboarding
   screens, then about 5 minutes to a first part. Trial users can't try any downstream module on their own part. After the
   first part, the dashboard doesn't suggest a next step. Also, Ctrl+Z doesn't undo model changes, the ribbon hides
   commands at 1366 px, and holes can't be placed by dimension.
   (PLT-07/08/09/13/14, STU-08..)

## What we are building from the 20 ideas (filtered for "not clutter")

| Idea | Why it wins |
|---|---|
| Run budget and live cost meter (PLT-IDEA-01) | Predictable AI cost. It fixes theme 1 at the root. |
| One start box: describe a part, or drop a STEP/PDF/photo (PLT-IDEA-02) | Fastest route to a first part. It replaces the template grid. |
| Release gate "Issue Rev A" (MAKE IDEA-01) | One staleness rule across all modules, carried in the handoff pack. |
| Fix-it loop from findings (MAKE IDEA-02) | Advice becomes a one-click design change, then a re-run that shows the delta. |
| Repair, don't block (Studio IDEA 1) | A broken feature shows what was lost, with Re-pick / Suppress / Ask the agent. |
| Fastener-aware Hole Wizard (Studio IDEA 3) | ISO 273 clearance/tapped/c'bore holes, edge-distance checks, no tokens. |
| Drawing round-trip check (AMI-I1) | Proves the model matches the source drawing, dimension by dimension. |
| "Fasten these two parts" (AMI-I2) | Every coaxial hole pair gets a stack, and mismatched holes get a one-click part fix. |
| If time allows: typed commands with no tokens, agent-filled PropertyManagers, assembly renders, catalogue view | |

## How it is being fixed

Four fixers work in parallel on branches `polish/{studio,platform,make,ami}`, each in its own worktree and on its own
port. Each one fixes every P0, then P1, then P2, then builds its selected ideas. Each writes
`audit/<area>-fixes.md` (finding → Fixed / Partly / Not done, with evidence). Each runs the full gate and a browser
walkthrough.

Ownership of shared code:
- The platform fixer owns token estimates and billing.
- The AMI fixer owns hole recognition.
- STU-18 (Make → Drawing loses the project behind the unlock page) is fixed by the master at merge.

The master merges, re-runs the gate and updates the punch list, session log and decisions.
