Auditor area: marketing site, pricing, legal, auth (signup, verify, login, reset), onboarding, guided tours, app shell
(sidebar, header, search, notifications), Dashboard, Projects list, Modules page, billing/plans/tokens/top-ups,
team/roles/invites, settings, Help, admin console and God mode, 404/error pages, design consistency.

Method: isolated app on port 8772 with its own data dir (`$SCRATCH/fw-e2e-8772`), headless Chrome (puppeteer-core),
desktop 1440/1600 px and phone 390 px. Signed up a **fresh non-admin user through the UI** ("Dana", verify via the dev
mailbox, 5-step onboarding, both tours, first part from a template with **one** live agent run), then walked every
platform page as the God-mode superadmin (seed demo, simulated checkouts, team invite, settings, admin tabs, dark
theme, collapsed sidebar, phone width). Password reset was exercised end to end via the admin outbox.

## 1. Verdict

The platform shell is clean, coherent and above the bar of most early SaaS: the auth pages, onboarding, dashboard,
billing and admin console look professional, the honesty labelling (SAMPLE, simulated payments, legal "draft") is
mostly disciplined, size search works, and a new user reaches a verified part with no dead ends. But a paying
designer would hit three things that undercut trust on day one. First, **the money story is wrong**: the UI promised
"≈ 40 tokens (20–80)" and "enough for several verified parts". The first template part cost **260 of the 300 trial
tokens**, and the user was told "Only 40 trial tokens left. Choose a plan" about 5 minutes after signing up. Second,
**the marketing surface breaks the product's own rules**: the hero shows "Write model.py" and "build_model" and claims
"manufacturable CAD". Third, **copy lags the product**: the tour, Modules page, pricing and landing still describe a
world where most modules are Preview, while a trial user cannot try any of the seven downstream modules (the real
differentiators) on their own part. Fix the token calibration, the hero, and the stale copy before anyone else signs up.
Then shorten the first-run path and make the "next step after the first part" obvious.

- **Dev mailbox on the verify page** (`j-04-verify-mailbox.png`): it makes the real journey testable without SMTP. Keep it, dev-only.
